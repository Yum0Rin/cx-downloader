本次是同一轮改动，共三件事：

1. **任务列表按「章节 / 资料」分组，可折叠**（第 2.1、2.2 节）
2. **修 bug：扫完再改「保存目录」不生效**（第 2.3 节）

  （v5 存档放的是 v5 改完后的代码，也就是 v6 动手前那一版）

---

## 1. 为什么改

v5 之后任务列表是平铺的，每个文件行靠文字前缀区分来源
（`章节 / 教学课件 / 第一章 操作系统引论 · xxx.pptx`）。一门课十几个文件时：

1. 前缀把每行都撑得很长，文件名反而被挤到看不见；
2. 章节 6 个 + 资料 6 个混在一起，想「只下资料」得一个个点；
3. 资料动辄几百 MB，平铺时容易看漏。

需求：**把「章节」和「资料」做成两个可折叠的分组**，组头能一眼看到数量和体积，
组内可以整组勾选/取消。

## 2. 改了哪些文件 / 核心差异

### 2.1 `cx_download.py`

- `scan_course` 给每个附件打上 `source = "章节"`。
- `scan_course_data` 给每个文件打上 `source = "资料"`，并且**不再**用
  `unit = "资料"` 这个 hack 占位（来源改由 `source` 表达，`unit` 留空）。
- 这两个字段只是给界面分组用，不影响下载。

### 2.2 `cx_download_gui.py`

**列表改成两级**：

```
┌────────────────────────────────────────────┐
│ [✓] ▾ 章节　6 个 · 待下载 6 · 约 5.5MB      │  ← 组头（点整条折叠/展开）
└────────────────────────────────────────────┘
      [✓] 课程介绍 / 课程大纲 · 2025级…docx    65.05 KB   新文件
      [✓] 课程章节 / 绪论 · 大数据…pptx        1.49 MB    新文件
┌────────────────────────────────────────────┐
│ [✓] ▾ 资料　6 个 · 待下载 6 · 约 834.6MB    │
└────────────────────────────────────────────┘
      [✓] dj2_preprocess_data · coupon.csv     470MB      新文件
```

- 新增 `build_label(unit, chapter, name)`：行文字变成 `分组 / 章节 · 文件名`，
  **不再重复写「章节 /」「资料 /」**（来源已经在组头上了）。
- 新增 `disp_width` / `elide` / `elide_mid`：按**显示宽度**（中文算 2）截断，
  而不是按字符数。空间不够时先压路径、再**从中间截断文件名**，
  保证扩展名还在（老实现直接把 `.docx` 截掉过）。
- 折叠用 `grid_remove()` / `grid()`：行会跟着塌掉，展开时还原原配置。
- 组头整条是一个 `CTkFrame`，勾选框放在**条里面**。第一版把勾选框单独放第 0 列，
  结果那一列被下面缩进过的子行撑宽，勾选框贴左边、横条却从很靠右开始，
  看着像两段缩进 —— 已修。
- 组头显示 `▾/▸ + 组名 + 个数 + 待下载数 + 合计体积`；组勾选框 = 该组全选/全不选。
- 点组头横条 = 折叠/展开；点组勾选框 = 整组勾选。折叠状态在重新扫描后保留。

### 2.3 修了一个真 bug：扫完再改「保存目录」不生效

任务行里的保存路径原来是**扫描那一刻**就算成绝对路径存下来的：

```python
"outdir": os.path.join(base_at_scan_time, 课程名)   # 旧写法
```

于是「先扫描 → 再改保存目录 → 点开始下载」时，文件仍然跑到**旧目录**去。
实际踩到的现象：用户把保存目录改成 `桌面\操作系统\课件`，点完下载那个文件夹
**是空的**，22 个文件全落在扫描时的 `桌面\示例课程\261学期 示例课程\` 里。

改法：任务里只存**课程子目录名**（`subdir`），绝对路径留到下载时按**当前**的
保存目录拼：

```python
job_dir = os.path.join(base, t["subdir"]) if t.get("subdir") else base
```

顺带两件事：

- 记下 `scan_base`（本次扫描时的保存目录）。**只有 `scan_base == 当前目录`**
  时才敢按 `exists` 直接覆盖；换过目录就按「没查过」处理，
  交给 `process_one` / `download_data_one` 的字节数校验兜底 ——
  同名的相同文件照样会跳过，不会白重下。
- 目录变了会在日志里明确提示「列表里的『已存在 / 内容相同』是扫描时那次判断的」。

### 2.5 新增：目录层级可勾选

以前落点固定是 `<保存目录>/<课程名>/<文件>`。现在「③ 选项」里多一行
**目录层级**，四级各自一个勾选框，**勾中哪级才建哪级**：

| 勾选项 | 对应的目录 | 举例 |
| --- | --- | --- |
| 课程名 | 课程名 | `261学期 示例课程` |
| 来源 | 章节 / 资料 | `章节` |
| 分组 | 章节所属的大类 | `课程介绍`、`课程章节`（「资料」没有这一级） |
| 章节名 | 章节标题 / 资料文件夹 | `课程大纲`、`dj2_preprocess_data` |

- 默认只勾「课程名」，跟老行为一致（配置里没有 `levels` 字段时也走这个默认）。
- 下面带一行**实时预览**，用列表第一项举例，勾选一变就重算，例如
  `预览：261学期 示例课程/章节/课程介绍/课程大纲/2025级信息…`
- 全不勾就直接落在保存目录里（不建任何子目录）。
- 「资料」的文件夹路径可能是多级的（`a / b`），勾「章节名」时会**逐级建**。
- 层级勾选和保存目录一起构成 `scan_key`：两者任一变了，就认为查重结果不再可信，
  按「没查过」处理，交给字节数校验兜底。
- 层级选择会写进 `~/.cx_download_gui.json` 的 `levels`，下次启动沿用。

### 2.4 `selftest.py`

`REQUIRED_CORE_ATTRS` 补上 `scan_course_data`、`download_data_one`

测试课程：`261学期 示例课程`（12 个文件 = 6 章节 + 6 资料）。

| 项 | 改动前（v5） | 改动后（v6） |

| `_collect_jobs` | 12 | 12（分组只影响显示） |

## 6. 已知限制

- **分组名来自 `source` 字段**，目前只有「章节」「资料」两种；
  裸 objectid 扫描出来的是「链接」组。
- 折叠状态存在内存里，关掉程序就重置（没有写进配置文件）。
- 组头的「约 X MB」是按扫描到的展示大小累加的估算值，不是精确字节数。
- 组勾选框只反映「全选 / 非全选」两态，没有做半选（indeterminate）样式。
