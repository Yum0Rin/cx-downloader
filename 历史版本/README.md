# 历史版本存档

每做一次**推倒重来式**的改动（重构、换算法、改口径、大规模重写），
都先把**改动前那一版**原样打包到这里，再动手改。

目录命名：`<改动名>-<语义化版本>-日期/`

版本号与 GitHub Release 的 tag 一一对应：

- 中间那位进位（`1.2.0` → `1.3.0`）是**大版本**，加功能、改结构；
- 最后一位进位（`1.3.0` → `1.3.1`）是**小版本**，修 bug、调细节；
- 目录名前缀写的是**这次改动要发布的版本号**，所以同一个大版本下可以有多个目录
  （比如 1.0.0 首发前连着改了好几轮）。

每个目录里有两样东西：

1. **改动前的源码**（原样存档，不参与当前交付）
2. **`README-历史版本说明.md`**，写清四件事：
   - 为什么改（触发改动的问题 / 需求变更）
   - 改了哪些文件、核心差异是什么
   - 改动前后的关键结果对比（数字、指标、结论差异）
   - 对下游交付物的口径影响 + 怎么回滚

顺序铁律：**先快照 → 再改动 → 后验证**。

## 回滚

想回到某个版本，把对应目录里的源文件覆盖回仓库根目录即可：

```powershell
Copy-Item 历史版本\资料页扫描-1.0.0-20260916\*.py . -Force
```

注意每个目录存的是**它自己那一版改动之前**的状态，所以
「回滚到 1.0.0」= 用最近一个 1.0.0 目录里的文件（那是它下一次改动动手前的样子）。
