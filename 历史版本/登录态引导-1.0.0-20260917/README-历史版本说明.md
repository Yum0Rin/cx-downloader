---

## 1. 为什么改

工具要发给同学用，但**课程链接里没有登录凭证** —— 实测同一个链接：

```
不带 cookie → <title>用户登录</title>     ← 服务器直接甩登录页
带 cookie   → <title>261学期 示例课程</title>
```

链接里的 `courseid / clazzid / cpi / enc` 只回答「要看哪门课」，不回答「你是谁」。
同学机器上没有登录态时，工具原来报的是「没解析出章节列表」——**看着像工具坏了，
根本想不到是没登录**。而且 Cookie 框埋在一堆选项里、placeholder 还写着「一般留空」。

目标：把「怎么弄到登录态」讲清楚，并且长说明不要糊在界面上。

## 2. 改了哪些文件 / 核心差异

### 2.1 `cx_download.py`

| 新增 | 作用 |
| --- | --- |
| `LoginRequired(RuntimeError)` | 专门表示「服务器返回的是登录页」，跟普通网络错误区分开 |
| `looks_like_login(html)` | 识别登录页（`<title>用户登录</title>` / `passport2.chaoxing.com` / `id="loginBox"` / `name="uname"`） |

- `_get_text()` 拿到响应后先判是不是登录页，是就抛 `LoginRequired`；
  HTTP 401/403 也归到这一类（原来是一句含糊的「请先在 Firefox 里登录」）。
- `fetch_course_name()` 对 `LoginRequired` **放行不吞**，让调用方能区分
  「没登录」和「取不到名字」。
- `fetch_course_chapters()` 里那句「可能是登录态失效」删掉 —— 登录页已经在
  更底层被拦下了，这里只剩「链接不对」一种可能。
- CLI 在没读到登录态时打印两种解决办法（Firefox / `--cookie`）。

### 2.2 `cx_download_gui.py`

**① 登录态状态行**

Cookie 框下面多一行实时状态，一眼看出现在用的是哪种登录态：

```
登录态：手动 Cookie（1122 字符）              ← 绿
登录态：本机 Firefox（16 条 chaoxing cookie） ← 绿
登录态：无 —— 扫描会拿到登录页，点左边 ⓘ 看怎么弄  ← 朱砂
```

**② 引导弹窗**

- 有课程页链接但**完全没有登录态**时：直接弹窗，并且**不再发起扫描**
  （省得白跑一趟）。纯预览链接 / objectid 不需要登录，不拦。
- 扫描过程中服务器返回登录页时：同样弹窗，日志写「登录态失效 —— 服务器返回的是登录页」。
- 弹窗内容：为什么需要登录 + 两条路（Firefox / 手贴 Cookie 的 5 步），
  底下三个按钮「从剪贴板粘贴 Cookie」「打开学习通登录页」「关闭」。

**③ Cookie 框**

- 加「粘贴」按钮。**允许直接粘整段请求头** —— 会自动只取 `Cookie:` 后面那截，
  并把折行、多余空白压掉（同学在 F12 里复制的往往就是整段）。
- 粘进来不像 Cookie（没有 `=`）会先确认一次。
- placeholder 从「一般留空；读不到 Firefox 登录态时再填」改成「留空则自动读 Firefox」。

**④ ⓘ 悬停说明（`HintIcon`）**

长说明一律收进圆圈 i，悬停弹出气泡：

| 位置 | 说明内容 |
| --- | --- |
| Cookie 旁边 | 怎么从 F12 拿到 Cookie（5 步）+ 过期提醒 |
| 自动跳过相同文件旁边 | 「内容相同」怎么判定的（字节数 + 前 64KB md5） |
| 目录层级旁边 | 四级各是什么、全勾/全不勾长什么样 |

实现上：CustomTkinter 没有 tooltip，用一个 `overrideredirect` 的**普通 Tk Toplevel**
现建现毁（不走 `CTkToplevel`，躲开它自己的缩放和延迟显示逻辑，位置更好控）。
颜色在弹出时按当前明暗主题现取，所以不用管主题切换重绘。

**踩到两个坑**（都已修）：

1. **字太小**。普通 Tk 字体**不跟** CTk 的 DPI 缩放走 —— CTk 的 `12` 在 175% 缩放下
   是 21px，而 Tk 的 `10` 是 10 磅 ≈ 13px，只有一半大。现在按
   `ScalingTracker.get_widget_scaling()` 换算成像素字号（Tk 里**负数 = 像素**）：
   `font=(FONT, -px(12))`，padding / 圆角 / wraplength 一并跟着缩。
2. **气泡是空的一块**。`Canvas.create_window()` 用的 widget **必须是这个 Canvas 的
   子控件**，挂在 Toplevel 上的话窗口项不渲染。得先建 Canvas、再以它为 master 建
   Label、量完尺寸后 `configure` Canvas 并画底。

边框改成 Canvas 画的圆角矩形（`round_rect()`，smooth 多边形），
圆角外面那圈用主窗口底色（`#16191E` / `#E9EDF2`）填，看着就像透明，
比原来「外框色 + padx=1」那种硬边好看，也跟界面里的卡片风格一致。

**⑤ 顺手修的布局问题**

`目录层级` 那行原来用 `CTkCheckBox`，**四个排不下**：`width` 填 70，
实际 `winfo_reqwidth()` 是 122（勾选框 + 内部间距），四个合计 466，远超左列 368。
改成自绘的 `LevelChips`（一排 CTkButton，选中态靠朱砂底白字区分，跟 `ToggleGroup` 一个路子），
合计 215，稳稳放得下。

## 3. 改动前后关键结果对比

| 场景 | 改动前（v6） | 改动后（v7） |
| --- | --- | --- |
| 无登录态点扫描 | 跑到服务器 → 报「没解析出章节列表」 | **不发起扫描**，弹引导弹窗 |
| Cookie 失效 | 报含糊错误 | 识别为登录页 → 弹引导，日志明确 |
| 日志末行（登录失败时） | 「扫描完成，但没找到任何附件」 | 「扫描中断：先把登录态弄好，再点「扫描」重试」 |
| 粘贴 Cookie | 只能手动 Ctrl+V 进输入框 | 一键粘贴，整段请求头自动截取 |
| 当前登录态 | 看不出来 | Cookie 框下实时状态行 |
| 长说明 | 无 | ⓘ 悬停弹出 |
| 目录层级四个选项 | **第 4 个被挤掉看不见** | 四个都放得下 |

实测（脚本探针）：

```
无登录态          → 弹窗 1 个，扫描线程未启动，标签「登录态：无 —— …」
填入 Cookie       → 标签「手动 Cookie（1122 字符）」，扫描到 11 个文件
Cookie 失效       → 弹窗 1 个，日志「登录态失效 —— 服务器返回的是登录页」
粘整段请求头       → 自动截取成 'uf=abc; _uid=999; vc3=zzz'
ⓘ 悬停           → 气泡 575x246，字号 -21px（跟正文一致），圆角卡片，移开即销毁
```

气泡两种主题都截图核对过：深色 `#20252C` 底 / `#D7DEE7` 字、浅色 `#FFFFFF` 底 /
`#2F4858` 字，圆角 + 1px 描边。

回归：正常扫描仍是 11 个章节附件、约 66.4 MB，下载逻辑一行没动。

## 6. 已知限制

- **没做 Chrome/Edge 自动读 cookie**，也不打算做：Chrome 127+ 的 App-Bound
  Encryption 一更新就可能失效，而且「读浏览器 cookie 库 + 解 DPAPI」是信息窃取
  木马的标准行为，杀软大概率直接拦 —— 对一个要发给同学的工具来说不划算。
  手贴 Cookie 已经覆盖所有浏览器（含手机），性价比高得多。
- 登录页识别靠几个特征字符串，学习通改版可能要跟着调 `LOGIN_MARKERS`。
- ⓘ 气泡只在悬停图标本身时显示，鼠标移向气泡会关掉（纯阅读用，不打算做成可交互）。
- 折叠状态、登录态状态行都不落盘，重启程序重置。
