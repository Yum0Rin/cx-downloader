# 历史版本：断点续传-v10-20261009

> **本目录内容 = 改动前（加断点续传之前）的那一版。**
> 当前正式版是仓库根目录里改动后的版本；本目录仅存档、不参与交付。

## 1. 为什么改

用户在「261学期 数智金融服务模式设计的基本方法与实践」用「仅 PDF」下载，卡住的 3 个文件最后报：

```
✘ 第二章 互联网券商_传统金融的互联网化.pptx
    下载失败: The read operation timed out
✘ 第0章 课程介绍-互联网金融的基本原理及三个关键词剖析(2026年3月2日修改版).pptx
    下载失败: The read operation timed out
✘ 第六章 互联网小额商业贷款_基于互联网平台开展金融业务.pptx
    下载失败: The read operation timed out
```

实测定位（同一文件 `第0章`）：

| 直链 | 节点 | 首次实测 | 预热后复测 |
| --- | --- | --- | --- |
| 原件 `download` | `d0.cldisk.com` | 6831 KB/s | —— |
| PDF `pdf` | `s3.cldisk.com` | 163 KB/s，中途停滞 | 4578 KB/s（3.85MB/0.9s） |

根因：**云盘 PDF 节点冷缓存**。首次访问要回源，吐一点数据后长时间停滞；而旧
`download()` 一超时就 `os.remove(tmp)` 然后从 0 重下，于是「下到卡点→超时→清零重下→再卡」，
3 次重试耗尽后报 `The read operation timed out`。缓存预热后同一文件本可秒下。

## 2. 改了哪些文件 / 核心差异

- `cx_download.py` 的 `download()`：
  - **出错不再删除 `.tmp`**（全部重试都失败才清）；
  - 每轮先读 `.tmp` 现有字节数，非 0 就带 `Range: bytes=<n>-` **从断点续下**；
  - 服务端忽略 Range（回 200）时自动回退整包重下；
  - 补 `416 Range Not Satisfiable` 处理：起点已到末尾 → 视为下载完成，直接改名返回；
  - `download_data_one` / CLI 共用此函数，一并受益。
- `CHANGELOG.md`：新增 `[Unreleased] → 修复` 条目。

其余文件未改动（`selftest.py` 未纳入本快照 —— 只改了一个函数）。

## 3. 改动前后关键结果对比

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| 冷节点 PDF（第0章 3.85MB） | 反复超时，最终失败 | 第 1 次拿部分 → 续传秒完（4033657B） |
| 本地模拟「吐 300KB 后卡住」 | 永远失败 | 续传成功，2MB 内容完全一致 |
| 失败后残留 | 无 `.tmp` | 保留 `.tmp` 供下次续传；彻底失败才清 |

验证：`第0章/第二章/第六章` 三个真实文件用 `process_one(..., want_pdf=True, timeout=20)` 全部 OK。

## 4. 对下游交付物的口径影响

- 之前记成「失败」的冷节点文件，重跑会转为「成功/已存在」，属预期。
- 断点续传会让**同一个 `.tmp` 在多次重试间保留**；因 `.tmp` 名 = 目标文件名 + `.tmp`，
  仍是按文件隔离的。若上一轮被杀进程留下 `.tmp`，下一轮会从它续下（这正是想要的行为）。
- 未发版；本机 exe 已用改动后源码重打并替换桌面 `大学の残骸\超星文件下载器.exe`。

## 补充：同批一起改的（v1.1.2 的「变更」）

本快照也早于下面这处改动，故一并说明：

- **视频任务点标「跳过」而非「失败」**：`process_one()` 新增 `VIDEO_EXTS` 与
  `_looks_like_video()`，当对象没有 `download/pdf` 但命中视频扩展名或带 `dtoken/duration`
  时，返回 `res["skip"]=True, skip_reason="视频，不支持"`，不计失败；CLI / GUI 汇总改为
  「成功 X / 跳过 Y / 失败 Z」。涉及 `cx_download.py` 与 `cx_download_gui.py`。
- 触发场景：课程「261学期 人工智能基础」扫出 89 项，其中 58 个 `.mp4` 全被记为失败。

## 怎么回滚

用本目录里的 `cx_download.py`、`cx_download_gui.py` 覆盖仓库根目录同名文件，再按项目流程
重打包即可。（本快照对应 v1.1.1 提交状态，即 v1.1.2 全部改动之前。）
